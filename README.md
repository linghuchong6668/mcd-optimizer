# 麦麦最优解 · Mcd Optimizer

> 在「预算 × 热量 × 人数 × 忌口」多重约束下，求解麦当劳最优下单方案的 Skill。
> 数据全部来自麦当劳 MCP Server 的真实接口，菜单、价格、营养、优惠券一律实时拉取，不做任何硬编码。

减肥期想吃麦当劳、两个人只有 70 块、团队下午茶要凑够 8 份还不能太咸——
这些本质上是同一个问题：**带约束的组合优化**。这个项目把它解出来，并给出三套方案：

| 目标 | 含义 |
| --- | --- |
| 最省钱 | 满足热量下限前提下的最低实付，附人均花费 |
| 最扛饿 | 每元买到的千卡最高（性价比） |
| 最均衡 | 蛋白供能比接近 20%、钠更低、总热量贴近目标 |

## 一键领券之后再求解

这是本项目和"随便挑几样"最大的区别：**它先帮你把券领了，再带着券去求解。**

```
auto-bind-coupons      → 一键领取可领的麦麦省券
query-store-coupons    → 查该门店当前可用券，以及每张券对应哪个商品
calculate-price        → 带 couponId/couponCode 真实核价，拿到真实实付
```

之所以必须这么做，是因为实测发现两个反直觉的坑：

- **券商品不在菜单里**。像「中薯条买一送一」是一个券专属商品（编码 `9900012387`），
  `query-meals` 里根本查不到。不单独建模，它永远进不了候选池——而它恰恰是最划算的选项。
- **不带券核价会静默丢件**。把它塞进订单但不带券，接口只返回其余商品的价格
  （实测"鸡排×2 + 薯条"返回 ¥28，薯条凭空消失），看起来更便宜，实际根本下不了单。
  所以只要方案里含券专属商品，就只认带券那次核价的结果。

## 为什么不是"随便挑几样"

1. **真实数据**：门店、菜单、现价/原价、营养成分全部由 MCP 实时返回，菜单换了项目不用改。
2. **套餐营养反推**：营养表里查不到的「XX三件套」，用 `query-meal-detail` 拆出默认组成
   （主食+小食+饮料）后逐项累加，营养覆盖率从 32% 提到接近全覆盖。
3. **券商品单独建模**：菜单里买不到的券专属商品，带券核价拿到真实到手价后再入池；
   「买一送一」类券还会把营养翻倍，避免把两份薯条的热量算成一份。
4. **约束建模**：主食件数、预算上限、热量上下限、忌口关键词同时生效，避免"最省钱=两个冰淇淋"这种废解。
5. **真实核价 + 预算复核**：本地枚举只解决搜索空间，最终价格一律回调 `calculate-price`。
   而且核价后会按**实付**再复核一次预算——菜单价是"起价"，套餐真实核价往往更高。
6. **多样性保留**：三个目标各自用自己的代理指标先排一遍、各贡献 1/3 名额再统一核价。
   否则先按价格砍到 N 个，最扛饿和最均衡就只能矮子里拔将军。

## 安装

纯 Python 标准库，无需 pip 安装任何依赖。

```bash
git clone https://github.com/linghuchong6668/mcd-optimizer.git
cd mcd-optimizer
```

准备麦当劳 MCP Token（获取方式见 [麦当劳 MCP Server](https://github.com/M-China/mcd-mcp-server)）：

```bash
export MCD_MCP_TOKEN=<你的 Token>
```

把 MCP 接入任意支持 Streamable HTTP 的客户端（示例见 `mcp-config.example.json`）。

### 生成可分享的 HTML 卡片

```bash
python3 scripts/optimizer.py --people 2 --budget 70 --kcal 800 --html docs/sample.html
```

会输出一张带券信息、性价比、营养指标的方案卡片（效果见 `docs/sample.html`，直接用浏览器打开即可）。

### 更多场景

```bash
# 减脂期单人餐：热量封顶 500 kcal，必须有主食
python3 scripts/optimizer.py --people 1 --budget 30 --kcal 500 --main 1

# 4 人加班餐，允许 2 件共享小食
python3 scripts/optimizer.py --people 4 --budget 150 --kcal 900 --extra 2

# 忌口 + 输出 JSON，方便接自己的前端
python3 scripts/optimizer.py --people 2 --budget 60 --avoid 辣,花生 --json

# 只想看现有卡包里的券，不想再领
python3 scripts/optimizer.py --people 2 --budget 60 --no-claim
```

## 常用参数

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `--people` | 用餐人数 | 1 |
| `--budget` | 总预算上限（元），0 表示不限 | 0 |
| `--kcal` | 每人热量上限（kcal），0 表示不限 | 0 |
| `--min-kcal` | 每人热量下限，默认取上限的 60% | 自动 |
| `--avoid` | 忌口关键词，逗号分隔 | 空 |
| `--extra` | 除主食外允许的共享附加件数 | 1 |
| `--main` | 主食件数下限 | 等于人数 |
| `--top` | 每种目标输出的方案数 | 1 |
| `--no-claim` | 跳过一键领券，只用现有卡包 | 关闭 |
| `--html` | 输出可视化 HTML 卡片 | 无 |
| `--json` | 额外输出结构化结果 | 关闭 |
